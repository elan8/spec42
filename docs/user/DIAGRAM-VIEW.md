# Diagram view

The **Diagram** view renders a diagram view authored in your model as an SVG. It lives in the
**secondary side bar** (right side of VS Code), in the **Spec42** container next to the
[Feature Inspector](FEATURE-INSPECTOR.md).

Diagrams are generated by a repository-owned WASM generator over the same immutable analysis
publication the editor and CI use, then drawn by the bundled renderer. The diagram is a
presentation of the resolved model — never a second place to define semantics.

## Opening the view

- Run **Spec42: Open Diagram** from the Command Palette, or
- Open the secondary side bar (**View → Secondary Side Bar**) and select **Diagram**.

If the secondary side bar is not visible, `Spec42: Open Diagram` reveals it and focuses the view.

## Choosing a view to render

Authored diagram views come from `view def` / `view` usages typed by a standard view definition
(for example `GeneralView`, `InterconnectionView`) with `expose` clauses that name the model
elements to include.

The toolbar dropdown lists every authored view in the model, grouped by the file that declares it.
Pick one and the diagram regenerates in place. If the model authors no views, the panel shows an
empty state with a hint.

## Staying in sync

The view re-generates on its own whenever the model changes — there is no manual refresh button.
The language server emits a notification after each workspace publication rebuild and the view
reconciles against it. A backoff reconcile loop runs whenever the view is visible and its render
does not match the current publication, so a slow index, a missed notification, a language-server
restart, or a stalled webview all recover with no user action.

## Toolbar

| Button | Action |
| --- | --- |
| **Home** | Fit and center the whole diagram. |
| **JSON** | Copy the generated diagram product (schema-versioned JSON) to the clipboard. |
| **SVG** | Export the current diagram as a standalone SVG file. |
| **PNG** | Export the current diagram as a PNG. |

`SVG` and `PNG` export re-render with a literal colour scheme so the file stands alone outside the
webview.

## Opening nested content

A general view starts with its exposed elements; the `+` on an element draws the members it
owns, and the `+` on a compartment lists them. An interconnection view starts with the exposed
parts and their direct parts. A part that has parts of its own carries the same `+`: opening it
draws the parts inside it and the connectors between them. A connector that ends inside a part
that is still closed ends on a dot at its boundary, labelled with the feature it stands for.

## Figures for documents

`spec42 diagram <path> --view <qualified name>` writes a view as an SVG that is as large as its
content. Without `--view` it lists the diagram views of the model.

| Option | Effect |
| --- | --- |
| `--depth <n>` or `--depth all` | For an interconnection view, how many levels of parts to draw below the exposed parts (default 1). |
| `--style <file>` | A JSON file with the house style of the figure. |
| `--format json` | The diagram product instead of the drawing. |
| `-o <file>` | Write to a file. |

A style file names a font family and any of the colours of the figure. What it leaves out keeps
the default:

```json
{
  "fontFamily": "Inter, sans-serif",
  "colors": {
    "canvasBackground": "#ffffff",
    "nodeFill": "#ffffff",
    "nodeBorder": "#003366",
    "edgeDefault": "#003366",
    "panelBackground": "#e6eef7",
    "textPrimary": "#001a33",
    "textSecondary": "#4d5d6c"
  }
}
```

The colours are `canvasBackground`, `panelBackground` (name compartments), `nodeFill`,
`nodeBorder`, `textPrimary`, `textSecondary`, `divider`, `highlight`, `edgeDefault`,
`frameStroke`, `frameText`, `badgeFill` and `badgeText`. Boxes are sized by the number of
characters in their text, so a font much wider than a common sans-serif can overrun them.

## Working with the Feature Inspector

The Diagram view is paired with the [Feature Inspector](FEATURE-INSPECTOR.md) in the same
container. Clicking a diagram node pins the inspector to that element; it then shows resolved
types, specialization / subsetting / redefinition, inherited features, relationships, values, and
source location. Use **Resume following cursor** in the inspector to go back to live editor
selection.

## View kinds

Spec42 projects the standard SysML view kinds — General, Interconnection, Action Flow, State
Transition, Sequence, Browser, Grid, and (partially) Geometry. Where a view's typed projection is
still incomplete the panel reports the typed reason rather than guessing. Coverage is tracked in
the [conformance matrix](../reference/CONFORMANCE-MATRIX.md).
